# ধাপ ২ — সম্পূর্ণ আর্কিটেকচার

```
ভিজিটরের ব্রাউজার / KORA ROYAL অ্যাপ (ওয়েবসাইটের রেপ্লিকা APK)
        │
        ├─ Netlify / Vercel  ← স্ট্যাটিক ফাইল (HTML/CSS/JS/sw.js)
        │
        └─ https://kora-api.shakhawatyt77.workers.dev  ← Cloudflare Worker v7.6
                 │
                 ├─ D1 (SQLite)   ← অর্ডার, প্রোডাক্ট, স্টক, কুপন, রিভিউ, কাস্টমার CRM,
                 │                   নোটিফিকেশন, বাগ-রিপোর্ট, লগ — সব কিছুর authoritative স্টোর
                 ├─ KV (KR_ORDERS)← লিগেসি অর্ডার মিরর (৯০ দিন TTL) + রেট-লিমিট কাউন্টার + ক্যাশ
                 ├─ Cron trigger  ← পুরনো ইভেন্ট ক্লিনআপ + শিডিউলড পুশ নোটিফিকেশন
                 │
                 ├─ Telegram Bot API    ← অর্ডার/লিড/রিভিউ নোটিফিকেশন + বট দিয়ে স্ট্যাটাস আপডেট
                 ├─ Google Apps Script  ← SHEETS_URL / LEAD_SHEETS_URL (অর্ডার+লিড শিটে সেভ)
                 ├─ Cloudinary          ← সাইনড ইমেজ আপলোড (f_auto,q_auto অপটিমাইজড URL)
                 ├─ Pathao Courier API  ← টোকেন-ক্যাশড বুকিং + ওয়েবহুক + প্রাইস/স্কোর
                 └─ Web Push (VAPID)    ← Firebase ছাড়া সরাসরি RFC 8291 এনক্রিপশনে পুশ
```

**ডেটা-ফ্লো (একটা অর্ডারের জীবনচক্র):**
1. ভিজিটর `index.html`-এ ফর্ম পূরণ করে → `main.js` ভ্যালিডেট করে → `api.js` → `POST /api/order` (Idempotency-Key হেডারসহ)।
2. Worker `placeCommerceOrder()`-এ: রেট-লিমিট চেক → আইটেম D1 থেকে রি-রিজলভ (দাম frontend থেকে বিশ্বাস করা হয় না) → কুপন সার্ভার-সাইড যাচাই → টোটাল পুনর্গণনা → এক atomic D1 batch-এ অর্ডার + আইটেম + হিস্ট্রি + কুপন রিডেম্পশন + স্টক রিজার্ভেশন লেখা।
3. এরপর KV মিরর + কাস্টমার CRM upsert + Telegram মেসেজ + Google Sheets রো — সব parallel (`Promise.allSettled`, একটা ফেল করলেও অর্ডার আটকায় না)।
4. ব্রাউজার `kr_last_order` সেভ করে `success.html?id=KR-...`-এ যায় — সেখানে D1 থেকে রি-ফেচ হয়, ৫-মিনিট ক্যানসেল কাউন্টডাউন চলে।
5. অ্যাডমিন অর্ডার confirm করলে স্টক রিজার্ভ → confirmed_sale-এ রূপান্তর, Pathao-তে পাঠালে consignment তৈরি + স্ট্যাটাস shipped। Pathao-র ২৪ রকম ওয়েবহুক ইভেন্ট এসে লোকাল স্ট্যাটাস আপডেট করে।
6. কাস্টমার `track.html`-এ ফোন-ভেরিফায়েড ইনভয়েস, ক্যানসেল, রিটার্ন/রিফান্ড/এক্সচেঞ্জ রিকোয়েস্ট করতে পারে।

**মূল ডিজাইন নীতি (পুরো কোডবেসে বারবার দেখা যায়):**
- **Server-authoritative:** দাম, ডেলিভারি চার্জ, কুপন, স্টক — সব Worker-এ পুনর্গণনা হয়। Frontend-এর হিসাব শুধু প্রিভিউ।
- **Graceful degradation:** D1 নেই? → KV লিগেসি পথ। কুপন টেবিল নেই? → হার্ডকোডেড ম্যাপ। Worker ডাউন? → `offline-mode.js` snapshot দেখায়। Telegram ফেল? → অর্ডার তবুও সফল।
- **Idempotency সর্বত্র:** অর্ডার, স্টক মুভমেন্ট, সেল ইভেন্ট, সার্ভিস রিকোয়েস্ট — সবখানে `idempotency_key UNIQUE` কলাম, ডাবল-ক্লিক/রিট্রাই নিরাপদ।

- **সেটআপ ফাইল না** — এটা একটা অবসরপ্রাপ্ত পেজ। নেভিগেশনে নেই, কোনো পেজ একে লিংকও করে না।
- **রায়: নিশ্চিন্তে কেটে দিতে পারেন।** শুধু `products.html` (রিডাইরেক্টটা) রাখলে ভালো — পুরনো বুকমার্ক বাঁচবে। `products-legacy.html` ডিলিট করলে কিছুই ভাঙবে না।

**courier.html — এটা কী:**

- এখন এই সব সেটিংস **pathao.html** (৫-ট্যাব) এবং **settings.html**-এ চলে গেছে। courier.html নেভিগেশন মেনুতেও নেই — মানে ডেভেলপার নিজেই এটাকে অবসরে পাঠিয়েছে কিন্তু ফাইলটা মুছেনি।
- এটা এখনও কাজ করে (একই API রুটে কথা বলে), তাই রাখলে ক্ষতি নেই — কিন্তু **একই সেটিংসের দুটো দরজা থাকা বিভ্রান্তিকর**।
- **রায়: কেটে দিতে পারেন।** কাটার আগে একবার pathao.html-এ ঢুকে দেখে নিন সব সেটিংস (sender info, store, instruction template) ওখানে দেখা/বদলানো যাচ্ছে কি না — গেলে courier.html-এর আর কোনো ভূমিকা নেই।

## 10.5 কমার্স কোর — টাকার হিসাব যেভাবে হয়
- **`checkOrderRate()`:** প্রতি IP ঘণ্টায় সর্বোচ্চ ২০টা অর্ডার-চেষ্টা (KV কাউন্টার)।
- **`resolveCommerceItems()`:** frontend শুধু productId/variantId/qty/selections পাঠায়। Worker D1 থেকে প্রোডাক্ট+অপশন+ভ্যারিয়েন্ট টেনে: active কি না, out_of_stock কি না, qty ১–৫০, required অপশন পূরণ হয়েছে কি না, ভ্যারিয়েন্ট ওই প্রোডাক্টেরই কি না — সব যাচাই করে **সার্ভারের দাম** দিয়ে লাইন বানায়। backorder বন্ধ থাকলে `stock_qty - reserved_qty`-এর বেশি কিনতে দেয় না।
- **`baseDeliveryFee()` + `calculateServerTotals()`:** ঢাকা-গ্রুপ ৬০/বাইরে ১৩০/ডিসকাউন্টের **পরের** সাবটোটাল ≥২৯৯৯ হলে ফ্রি; advance টোটালের বেশি হতে পারে না; codRemaining হিসাব।
- **`resolveCoupon()`:** status→validity window→min_subtotal→global limit→per-customer limit (ফোন-ভিত্তিক, redemptions টেবিল গুনে)→টাইপ অনুযায়ী হিসাব: percent (max_discount cap সহ, apply_base subtotal/total), fixed, free_delivery, **BOGO** (প্রতি লাইনে `floor(qty/(buy+get))*get` ইউনিট ফ্রি)। প্রতিটি ব্যর্থতার নিজস্ব ইংরেজি মেসেজ — সেটাই কাস্টমার দেখে।
- **`placeCommerceOrder()`:** ডুপ্লিকেট আইডি হলে আগের অর্ডারই ফেরত (idempotent); সব ইনসার্ট+রিজার্ভেশন **এক D1 batch**-এ (atomic — মাঝপথে ফেল হলে কিছুই লেখা হয় না); কুপন used_count বাড়ে `WHERE used_count < limit` গার্ডসহ (race-safe); তারপর KV মিরর, CRM upsert, Telegram+Sheets।
- **`validateStatusTransition()`:** র‍্যাঙ্ক-ভিত্তিক শুধু-সামনে-যাওয়া (pending→confirmed→packing→packed→shipped→delivered) + after-sales ব্যতিক্রম টেবিল (delivered→returned/refunded/exchanged ইত্যাদি); `cancelled_by_seller` শুধু শিপের আগে।
- **`transitionCommerceOrder()`:** pending→(যেকোনো সামনের ধাপ) প্রথমবারে "confirmation" ট্রিট হয়: reserved_qty→stock_qty কাটা, `confirmed_sale` মুভমেন্ট, `product_stats.website_sold` +qty, `sold_credited=1` — সব এক batch-এ। **returned-এ অটো-রিস্টক হয় না** — ইচ্ছাকৃত; Telegram-এও মনে করিয়ে দেয়: "Inventory → Stock In দিয়ে ম্যানুয়ালি রিস্টক করুন"।
- **`commerceAdminStats()`:** দিনের শুরু **বাংলাদেশ টাইমজোনে (UTC+6)** হিসাব হয়; revenue = delivered+exchanged − রিফান্ড-অ্যাডজাস্টমেন্ট।

## 10.6 Pathao ইঞ্জিন (v6 রিবিল্ড) — পুরো গল্প
- **টোকেন:** `getPathaoAccessToken()` — mode-ভেদে (sandbox/live) আলাদা KV ক্যাশ; Pathao 401 দিলে টোকেন invalidate করে **একবার** অটো-রিট্রাই।
- **লিস্ট ক্যাশ:** city/zone/area লিস্ট ২৪-ঘণ্টা KV ক্যাশ (`?refresh=1` দিয়ে জোর-রিফ্রেশ)।
- **Address matching engine:** বাংলা-ইংরেজি নর্মালাইজেশন (`pathaoNormKey`), stop-token বাদ, **Levenshtein distance ≤1** fuzzy ম্যাচ, স্কোরিং (exact=100, prefix, fuzzy=65...)। `pathaoResolveAddress()` প্রথমে **শেখা টেবিল** `pathao_address_map` দেখে (আগে অ্যাডমিন যা ঠিক করেছে), তারপর হার্ডকোডেড জেলা→সিটি ম্যাপ, তারপর fuzzy — confidence সহ ফেরত দেয়।
- **`bookPathaoOrder()` — একমাত্র বুকিং পথ:**
  1. ইতিমধ্যে consignment থাকলে `alreadyBooked` ফেরত; cancelled অর্ডার ব্লক।
  2. নাম ৩–৬৪ অক্ষর, ফোন ১১-ডিজিট BD, ঠিকানা ≥১০ অক্ষর যাচাই (Pathao-র আসল 422 মেসেজ থেকে ভেরিফায়েড লিমিট)।
  3. **Address strategy:** অ্যাডমিন ম্যানুয়ালি city/zone দিলে তাই; নইলে resolver confident হলে তার ids; নইলে **auto মোড** — city/zone/area একদমই না পাঠিয়ে Pathao-কে ঠিকানা-টেক্সট থেকে geocode করতে দেওয়া (জুলাই ২০২৫-এর Pathao-র অফিসিয়াল সুপারিশ, কমেন্টে ব্লগ-লিংকসহ)। auto হলে ঠিকানা ≥১৫ অক্ষর লাগবে।
  4. **ডাবল-বুকিং লক:** `pathao_booking_locks` টেবিলে PK-insert = atomic লক; ১২০ সেকেন্ডের পুরনো লক অটো-মুছে; `finally`-তে লক রিলিজ।
  5. বুক সফল হলে: `courier_shipments` রো (পুরো পাঠানো payload + Pathao-র response JSON সংরক্ষিত — পরে ডিবাগযোগ্য), হিস্ট্রি নোট, লোকাল স্ট্যাটাস → **shipped**, KV মিরর, audit।
  6. **শেখা:** সফল ম্যাপিং `pathao_address_map`-এ মনে রাখে — কিন্তু থানা ambiguous হলে না (যেমন "Uttara" Pathao-তে ১৯টা সেক্টর-জোনে ম্যাচ করে — পিন করলে ভুল হবে, তাই প্রতিবার ঠিকানা-টেক্সট দিয়েই সিদ্ধান্ত)।
- **`maybeAutoBookPathao()`:** Settings-এ `pathao_auto_book=1` থাকলে কনফার্মের সময় অটো-বুক — কিন্তু **শুধু confident ঠিকানায়**; নইলে চুপচাপ ম্যানুয়াল ব্যাচের জন্য রেখে দেয়। ডিফল্ট OFF।
- **এক্সট্রা:** `pathaoPricePlan` (ডেলিভারি চার্জ আগে থেকে), `pathaoCustomerScore` (ফোন নম্বর দিয়ে Pathao-র কাস্টমার সাকসেস-রেট — ফেক-অর্ডার চেনার অস্ত্র), `pathaoSyncShipment` (pull-ভিত্তিক স্ট্যাটাস সিঙ্ক; র‍্যাঙ্ক পেছনে যায় না)।
- **ওয়েবহুক `/api/pathao/webhook`:** প্রতিটা রেসপন্সে `X-Pathao-Merchant-Webhook-Integration-Secret` হেডার (Pathao-র চুক্তি); দুই সিক্রেট (integration + signature); **সব হিট** (unverified-ও) `pathao_webhook_log`-এ (সর্বশেষ ~২০০০ রাখা হয়); consignment_id → না মিললে merchant_order_id দিয়ে লিংক (Pathao প্যানেল/CSV থেকে বুক করা অর্ডারও অটো-লিংক হয়ে যায়!); `PATHAO_EVENT_MAP`-এ **২৪ রকম ইভেন্ট** → লোকাল স্ট্যাটাসে অনুবাদ (`applyCourierEvent`), কুরিয়ার-র‍্যাঙ্ক পিছনে গেলে ইগনোর; delivered/returned/partial ইভেন্টে Telegram-এ জানায়, returned-এ রিস্টক-রিমাইন্ডার।

## 10.7 Telegram — দুই দিক
- **পাঠানো:** `sendTelegramMsg()` (HTML parse_mode)। নতুন অর্ডার, কাস্টমার-ক্যানসেল, ম্যানুয়াল অর্ডার, রিভিউ, বাগ-রিপোর্ট, Pathao ইভেন্ট — সব মেসেজ টেমপ্লেটেড (emoji + `<code>` অর্ডার-আইডি, কপি করা যায়)।
- **গ্রহণ (বট-কমান্ড!):** `/api/telegram/webhook` — `TELEGRAM_WEBHOOK_SECRET` হেডার-শিল্ড + শুধু অনুমোদিত chat id। গ্রুপে `#status_update` লিখে `Order ID: ...` + `Status: Confirmed/Shipped/...` + `Note: ...` পাঠালে Worker অর্ডার স্ট্যাটাস বদলে দেয় — **অ্যাডমিন প্যানেল না খুলেই Telegram থেকেই অর্ডার ম্যানেজ**। ১২ রকম স্ট্যাটাস-শব্দ চেনে, ভুল হলে বটই উত্তর দিয়ে শুধরে দেয়; confirmed/packing/packed-এ অটো-Pathao চেষ্টাও করে (অপশন অন থাকলে)।

## 10.8 Cloudinary
- `cloudinaryUpload()` — SHA-1 সাইনড আপলোড (সিগনেচার প্যারামিটার alphabetical — v5.1-এ ফিক্সড); ফেরত URL-এ `f_auto,q_auto,w_*` ট্রান্সফর্ম বসিয়ে অপটিমাইজড ভার্সন সেভ হয়।
- `sniffImageDataUri()` — ঘোষিত MIME বিশ্বাস না করে **ম্যাজিক বাইট** চেক (JPEG/PNG/WebP/AVIF/HEIC/SVG) — ইমেজের ছদ্মবেশে অন্য ফাইল আপলোড আটকায়।
- `cloudinaryUploadRaw/DestroyRaw` — APK ফাইলের জন্য raw আপলোড/ডিলিট (app-releases)।

## 10.9 নোটিফিকেশন ইঞ্জিন v1.0 (Firebase ছাড়া)
- **VAPID + RFC 8291 (aes128gcm) এনক্রিপশন সম্পূর্ণ হাতে লেখা** — HKDF, ECDH, AES-GCM সব `crypto.subtle` দিয়ে। কোনো third-party পুশ সার্ভিস নেই।
- **Audience targeting:** all / নির্দিষ্ট ফোন-লিস্ট / ফিল্টার; টেমপ্লেট ভেরিয়েবল (`{date}`, `{time}` বাংলা সংখ্যায় — `krToBnDigits`)।
- **ব্যাচ পাঠানো:** এক টিকে সীমিত ব্যাচ; বাকি থাকলে `pending_batch=1` + ২০ সেকেন্ড পরে cron ধরে নেয় — হাজার সাবস্ক্রাইবারেও Worker টাইমআউট হয় না।
- **রেজাল্ট ট্র্যাকিং:** প্রতি সাবস্ক্রাইবারে delivery রেকর্ড; `410 expired` হলে সাবস্ক্রিপশন নিষ্ক্রিয়; delivered/failed কাউন্টার; ক্লিক ট্র্যাকিং।
- **`app-local:` এন্ডপয়েন্ট:** APK অ্যাপের web-push নেই — তার সাবস্ক্রিপশন শুধু inbox-এ লেখা হয়, অ্যাপ নিজে পোল করে।
- **রিকারেন্স + র‍্যান্ডম টাইম:** daily/weekly রিপিট, এমনকি "প্রতিদিন X–Y টার মধ্যে র‍্যান্ডম সময়ে" পাঠানোর অপশন; expired নোটিফিকেশন অটো-বাদ; inbox ৯০ দিন, deliveries ১৮০ দিন পরে অটো-ক্লিনআপ।
- **`scheduled()` cron:** প্রতি টিকে — ৩০-দিনের পুরনো cart/view ইভেন্ট ক্লিনআপ (এক টেবিল মিস করলেও cron থামে না — try-wrap) + `krNotifyCronTick()`।

## 10.10 সিকিউরিটি স্তর
- **CORS:** `ALLOWED_ORIGIN` তালিকা + localhost/LAN-IP রেঞ্জ ডেভের জন্য অনুমোদিত; `Vary: Origin`।
- **অ্যাডমিন টোকেন:** নিজস্ব মিনি-JWT — base64url(payload: iat/exp-8h/nonce) + HMAC-SHA256 সিগনেচার; `constantTimeEqual` দিয়ে টাইমিং-অ্যাটাক প্রতিরোধ; **প্রতিটি** admin রুটের প্রথম লাইন `verifyAdmin()`।
- **লগইন রেট-লিমিট:** IP-হ্যাশ ভিত্তিক ৮ ভুল/১৫ মিনিট (client-side ৫/৫-মিনিটের অতিরিক্ত স্তর)।
- **ইনপুট স্যানিটাইজেশন:** সব ইনপুট `cleanText/cleanToken/positiveInt/validOrderId(regex KR-...)/validHttpsUrl` দিয়ে; Telegram-এ সব আউটপুট `htmlEsc`; `readJson` সাইজ-লিমিটেড।
- **Audit log:** প্রতিটা অ্যাডমিন অ্যাকশন (স্ট্যাটাস বদল, কুপন, বুকিং, কাস্টমার এডিট...) `audit_log`-এ কে/কখন/কী।
